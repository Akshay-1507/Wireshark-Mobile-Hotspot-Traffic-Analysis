# Wireshark-Mobile-Hotspot-Traffic-Analysis
Hands-on Wireshark project analyzing network traffic generated by a mobile phone connected to a laptop's Wi-Fi hotspot. Explored DNS, TCP, UDP, TLS, QUIC, IP addresses, and application-related network activity through practical packet capture and analysis.
**WIRESHARK – MOBILE HOTSPOT
NETWORK TRAFFIC ANALYSIS
Hands-on Network Analysis Project | Prepared by Akshay**
 
**1. Project Overview**
I completed a hands-on Wireshark project to understand how network traffic can be captured and analyzed in a small home environment. My laptop was connected to the internet through an existing Wi-Fi network. I enabled Windows Mobile Hotspot and connected my mobile phone to the laptop hotspot. I then generated normal application activity, including Instagram usage and camera-related activity, and inspected the traffic visible in Wireshark.
The objective was to learn packet capture, protocol identification, IP addressing, ports, DNS, TCP, UDP, TLS, and the limitations of analyzing encrypted application traffic.
**2. Objectives**
•	Capture live network traffic using Wireshark.
•	Identify the appropriate network interface for the hotspot client traffic.
•	Inspect source/destination IP addresses and port numbers.
•	Analyze DNS queries, TCP/UDP communication, TLS and QUIC traffic.
•	Compare network activity during idle, Instagram, and camera tests.
•	Understand encrypted traffic and privacy considerations.
**3. Lab Setup**
Laptop: connected to the existing Wi-Fi network and sharing internet through Windows Mobile Hotspot. Mobile phone: connected to the laptop hotspot. Wireshark: installed on the laptop and used to capture traffic from the interface that exposed the phone's traffic.
The diagram shows the logical topology. Actual packet visibility depends on the Windows hotspot implementation, adapter/driver behavior, and selected capture interface. The physical Wi-Fi uplink may not expose every packet generated by the phone.
****4**. Methodology******
4.1 Configure the hotspot
•	Connect the laptop to the normal Wi-Fi network.
•	Enable Settings → Network & Internet → Mobile hotspot.
•	Connect the mobile phone to the laptop's hotspot.
•	Open Wireshark and inspect available physical and virtual network interfaces.
•	Identify the interface showing traffic from the phone by comparing idle and active traffic.
4.2 Capture baseline traffic
With the phone connected and idle, capture a short baseline. Note background DNS, connectivity checks, keep-alive traffic, and other visible activity.
4.3 Analyze Instagram activity
Start a separate capture or note the capture start time. Open Instagram on the connected phone, browse the feed, and load posts or reels. Inspect DNS queries, destination IPs, TCP/TLS/QUIC traffic, packet sizes, and timing. Encrypted application content should not be expected to appear as readable text.
4.4 Analyze camera activity
Start a separate capture, open the phone's camera, and take a photo. Observe whether network traffic changes. A local photo capture does not necessarily create internet traffic. Network activity may occur if the image is uploaded, backed up, synchronized, or shared. Record the exact action performed.
4.5 Compare captures
Compare baseline, Instagram, and camera test captures. Look for changes in packet volume, DNS requests, endpoints, transport protocols, and connection timing. Do not attribute a packet to a specific application solely from an IP address without corroborating evidence.

6. Packet Investigation
•	Frame: frame number, timestamp, and packet length.
•	Link layer: link-layer addresses and frame information, depending on capture type.
•	IP layer: source and destination addresses.
•	Transport layer: TCP/UDP, ports, TCP flags, and sequence details.
•	Application layer: decoded DNS, TLS, QUIC, HTTP, or other protocol information.
Useful Wireshark menus include Statistics → Protocol Hierarchy, Statistics → Conversations, and Statistics → Endpoints.
7. Key Learnings
•	Packet captures only show traffic visible at the selected capture point.
•	DNS resolves domain names to IP addresses.
•	TCP is connection-oriented; UDP is connectionless and is used by DNS and QUIC.
•	TLS/HTTPS encrypts application content; metadata such as endpoints, ports, timing, and some handshake details may remain visible.
•	QUIC commonly uses UDP and is associated with HTTP/3.
•	Background services can generate traffic even when an application is not actively being used.
•	Testing one activity at a time and recording timestamps improves analysis accuracy.

Use genuine screenshots from your own lab. Do not fabricate packet evidence. Review and sanitize screenshots and PCAP/PCAPNG files before publishing; remove credentials, cookies, tokens, private browsing details, device identifiers, and unrelated traffic.
**9. Security and Privacy**
•	Capture only devices and networks that you own or are authorized to analyze.
•	Do not intercept or attempt to access another person's private communications.
•	Do not publish raw captures containing sensitive information.
•	Do not include hotspot credentials, passwords, session tokens, or personal information in the repository.
•	Treat application names as test labels, not proof that every packet belongs to that app.
**10. Conclusion**
This project provided practical experience with Wireshark and network traffic analysis using a laptop-hosted mobile hotspot. By generating controlled activity from a connected phone, I learned to inspect packet metadata, identify protocols, examine DNS and transport-layer communication, and recognize encrypted traffic. I also learned that packet visibility depends on the capture interface and network path, so the correct adapter must be validated before drawing conclusions.
